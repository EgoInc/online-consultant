# Онлайн-консультант

Каркас двух ВКР с API и двумя демонстрационными сценариями.

```text
chat-app-example/       React-приложение: подключение каталога и сценарий диалога
web-app-module/         пустая папка для ВКР 1, только .gitkeep
backend/
  catalog/engine.py     методы импорта, нормализации и поиска — ВКР 2
  api/                  endpoints, валидация, Swagger и отдельные моки API
  config/               настройки Django
  compose.yaml          отдельный запуск backend и PostgreSQL
docker-compose.yml      совместный запуск приложения, backend и PostgreSQL
```

## Запуск всего проекта

Нужен Docker Desktop с включённым Linux engine.

```sh
docker compose up --build
```

- Подключение каталога: http://localhost:3000/#connection
- Сценарий диалога: http://localhost:3000/#dialog
- Swagger: http://localhost:8000/docs
- Проверка API: http://localhost:8000/health

Настройки по умолчанию работают без `.env`. При необходимости скопируйте `.env.example` в `.env`. После изменения исходников пересоберите контейнеры той же командой. Остановка: `docker compose down`. Данные PostgreSQL остаются в Docker volume.

## Демо-сценарии

«Чат» — мессенджер на сайте магазина. «Подключение» — кабинет владельца магазина на сайте нашего ИИ-консультанта. В рабочем проекте это разные сайты; в демо они объединены боковым переключателем. При открытии приложения первым показывается чат.

**Подключение каталога** отправляет настоящий `POST /api/v1/stores`. Для API передаётся JSON:

```json
{
  "name": "Магазин освещения",
  "source_type": "api",
  "catalog_url": "https://shop.example/api/products",
  "product_url_template": "https://shop.example/api/products/{id}"
}
```

Второй вариант — `multipart/form-data`: поля `name`, `source_type=file` и `file`. Принимаются файлы XML/YML размером до 10 МиБ. Формат запроса проверяется на сервере; содержимое каталога пока не разбирается.

Для корректного запроса endpoint вызывает незавершённый `CatalogEngine.connect` и отвечает HTTP `501`, код `CATALOG_NOT_IMPLEMENTED`, сообщение «Метод ещё не реализован.». Сейчас товары не загружаются и данные подключения не записываются в БД. Экран показывает этот ответ, успешное подключение не имитируется.

**Диалог про люстру** работает полностью локально. Первая реплика уже заполнена при открытии чата. Четыре заранее заданные реплики пользователя нельзя редактировать: отправка добавляет сообщение и ответ консультанта с демонстрационными товарами, затем подставляет следующую реплику. После уточнений меняется подборка; в конце остаются две белые люстры до 20 000 ₽ с заявленной площадью освещения от 12 м². После последнего шага поле ввода и отправка отключаются. Текст и товары возвращает `getDemoReply` в `chat-app-example/src/dialogue-demo.ts` — источник моков для последующей замены ответами реального модуля. Запросы к backend из чата пока не отправляются.

## Кто что делает

- **ВКР 1 — `web-app-module/`.** Студент реализует React-модуль и встраивает его в чат. Папка содержит только `.gitkeep`, не участвует в зависимостях и сборке.
- **ВКР 2 — `backend/catalog/engine.py`.** Студент реализует получение полного каталога, анализ и семантическое сопоставление полей, нормализацию, сохранение в нашу БД, индексы и поиск. Методы пока завершаются `NotImplementedError`.
- **Промежуточный слой — `backend/api/`.** Принимает и проверяет запросы, вызывает модули и формирует ответы. Схемы запросов и ответов описаны в DRF-сериализаторах и Swagger.

Целевая цепочка: API магазина или файл → импорт и нормализация → наша БД → поиск по нашей БД. Шаблон URL одного товара позволяет получать его подробности при импорте. Поиск консультанта должен работать с импортированным каталогом.

## Отдельная проверка API

Помимо локального сценария доступны серверные endpoints:

- `POST /api/v1/stores/{store_id}/dialog/messages` — сообщение, ответ консультанта, обновлённый `state` и товары.
- `POST /api/v1/stores/{store_id}/search` — поиск по запросу и ограничениям.
- `GET /api/v1/stores/{store_id}/status` — состояние каталога.

По умолчанию `CATALOG_PROVIDER=mock` и `DIALOG_PROVIDER=mock`. Для проверки через Swagger есть магазины `demo-store` и `demo-lighting`. Параметр `scenario` задаёт варианты мокового ответа; состояние диалога передаётся в `state` между запросами. Эти моки не импортируют каталоги и не обращаются к LLM.

Переключение каталога в `CATALOG_PROVIDER=real` подключает методы `CatalogEngine`; пока они пустые, статус и поиск отвечают `503`. Подключение нового каталога отвечает `501` при любом провайдере. Точка подключения настоящего диалогового модуля находится в `backend/api/services.py`.

## Разработка

Backend можно скопировать на отдельный сервер и запустить независимо:

```sh
cd backend
docker compose up --build
```

Для React без Docker нужен Node.js 22.13+. Из корня:

```sh
npm ci
npm run dev
```

`npm run build` собирает приложение в `chat-app-example/dist/`. Проверка типов: `npm run typecheck`.

Проверка серверного слоя:

```sh
docker compose build backend
docker compose run --rm --no-deps backend python manage.py test
```

Зависимости, сборки, кэши и локальные `.env` исключены через `.gitignore`.
